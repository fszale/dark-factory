# Configuration and release runtime

Copy `.env.example` to `.env` for local server settings. The browser does not read `.env` secrets. Provider configuration is optional: without configured provider credentials, the deterministic factory view remains usable and the UI should report provider availability accurately.

| Variable | Used by | Purpose |
| --- | --- | --- |
| `OPENAI_API_KEY` | Server provider adapter | Enables GPT-6 Astra Responses requests. |
| `TYPESAFE_API_KEY` | Server provider adapter | Enables TypeSafe Jev SDK requests. |
| `PORT` | Fastify runtime | Single externally served port; default is 3000. The server always binds `0.0.0.0`. |
| `PUBLIC_MODE` | Server access gate | Set to `true` on an internet-facing deployment to require an access code before provider calls. |
| `BRICKWORKS_ACCESS_CODE` | Server access gate | Shared provider access code for public mode. It is accepted in the session, chat, or Jev request body and is never returned. |
| `AI_GLOBAL_TOKEN_LIMIT` | Server provider coordinator | Completed provider-token budget per server process and wall-clock hour; default is 100,000. |
| `SESSION_IDLE_MS` | Session manager | Idle lifetime for a session with no live socket; default is 30 minutes. |
| `ARCHIVE_DIR` | Audit archive | Private server directory for per-session NDJSON history; default is `.data/archives` under the server working directory. |
| `ARCHIVE_RETENTION_MS` | Audit archive | Retention after the most recent archived record; default is 24 hours. |
| `ARCHIVE_SESSION_BYTES` | Audit archive | Per-session disk limit; default is 64 MiB. |
| `ARCHIVE_GLOBAL_BYTES` | Audit archive | Total disk limit; default is 256 MiB. |

The production image uses Node 22, builds the Vite client, server, experiment worker, and replay worker bundles, and starts `dist/server/index.js` on port 3000. Replit's Reserved VM configuration likewise starts the built application on one `0.0.0.0:3000` endpoint. Avoid placing provider keys in client environment variables, source code, exports, screenshots, or logs.

Provider `configured` status means that the corresponding environment variable is nonempty. It does not validate the credential at startup or promise provider availability. A request can still fail because of authentication, quota, service, or network errors; the server records a generic failed decision, holds factory settings, and never substitutes a simulated AI answer. Local mode allows configured provider calls without an access code. Public mode requires `PUBLIC_MODE=true` and a matching `BRICKWORKS_ACCESS_CODE`; setting public mode without a code keeps provider calls locked.

The adapters were implemented against the installed OpenAI JavaScript SDK 7.20.0 Responses API (`responses.create`, GPT-6 Astra, strict JSON-schema output) and TypeSafe AI SDK 0.6.0 (`TypeSafeClient.systemOne` with a `choice` question). The lockfile pins the installed dependency graph. Only current operational telemetry, active order queue, recent completed experiment evidence, and the current order/replenishment/dispatch configuration are sent: the provider view omits seed, station wear, simulation random streams, checkpoint internals, and future fault state. Astra output is restricted to bounded operational commands and capped at 600 output tokens. Its configuration actions are allowlisted to release rate, reorder point, delivery size/lead, dispatch dwell, order size, loading capacity, continuous mode, per-line material priority, bounded order creation/reprioritization, and one paired-profile experiment with server-validated ranges; it cannot change seed or create faults. Jev selects one bounded action. Per-session wall-clock limits are two Astra and twelve Jev calls per minute, with at most one process-wide in-flight request per provider.

Decision records keep the KPI source view, simulation-time application point, and one validation outcome per proposed action. A later baseline/measurement pair covers no more than 120 simulated seconds and is explicitly labeled observational rather than causal. Recorded-AI comparisons use only live applied decisions held in the current server process; checkpoint imports, graphical replay, rejected/advisory decisions, and pre-reset actions cannot seed that policy. The comparison is open-loop action replay across paired seeds and makes no adaptive-AI or causal claim. A provider-requested experiment uses the same worker limits, never enters the live manufacturing command engine, and records paired deterministic-simulation provenance only if control remains current. Its candidate recommendation is evidence for a later response; it never applies configuration implicitly.

The live snapshot and runnable checkpoint intentionally retain bounded event windows. The server separately writes a full chronological NDJSON archive containing the initial checkpoint, events, command outcomes, completed-vehicle lineage, and periodic/final time watermarks. `GET /api/sessions/:id/history` requires the session token and remains available after process restart until retention or disk quota cleanup removes it. `POST /api/sessions/:id/replay` with `{time}` and the same token creates a new paused session. Time is interpreted within the latest archived reset epoch; complete earlier epochs are applied first, and watermarks bound event-free intervals without predicting beyond observed runtime. Replay runs in a bounded worker and rejects a truncated archive rather than inventing missing history. The server stores only a SHA-256 digest of the high-entropy token beside the archive. If a configured quota is reached, the archive records an explicit `archive-truncated` marker and the response sets `x-archive-truncated: true`; it never silently presents a partial file as complete. Treat `ARCHIVE_DIR` as private operational data and keep it off a public static volume.
