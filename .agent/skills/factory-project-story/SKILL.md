# Factory Project Story

Use `README.md` as the GitHub landing page, `docs/assets/README.md` for image provenance and `docs/release-evidence.md` for demonstrated results. Paths are relative to the repository root.

The founder's direction: build and learn from a virtual dark factory first; next build a physical tabletop factory using LEGO-style bricks or similar mechanics; then seek an investor and a plant partner to manufacture useful parts for future industry. The robotaxi is the initial reference product, not a commitment that the eventual plant manufactures cars.

- Lead with a striking, repository-hosted image, the live Replit link and an accessible description of the production journey.
- Clearly label generated concept art as a visual target. Include actual application captures and identify them as such. Do not present a target image as a delivered render.
- Keep the origin story personal and ambitious, but distinguish implemented capabilities, approved plans and longer-term aspirations. Do not imply secured investment, a commissioned plant, physical validation or demonstrated real-world economic gains.
- Preserve the practical developer path: Node 22 setup, commands, server-only credentials, architecture, tests, asset attribution and MIT license.
- Keep the five-module educational adaptation distinct from Tesla's engineering and retain the independent-model notice. No implied LEGO/Tesla endorsement.
- Prefer existing original images with known provenance. Keep repository-relative image links portable on GitHub; use the verified HTTPS demo URL.
- When changing public claims, inspect their evidence and current deployment status. Avoid unmaintained exact counts or assertions that configured keys prove working model calls.

Validate local links and skill frontmatter, review the rendered GitHub page after an authorized push, and ensure the public story and detailed roadmap agree. Documentation work does not authorize executing the graphics upgrade or changing production behavior.
